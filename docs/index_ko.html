ADK Root ↔ Sub-Agent(BQCA) State·Stateless·Memory·Routing 개선 및 2-Tier Token 최적화 검증

전사 NL2SQL Platform 연동 PoC에서 고객이 직면하는 2대 핵심 기술 과제인 1) ADK 기반 Root Agent와 Sub-Agent(BQCA) 간 State·Stateless·Memory·Routing 최적 설계와 2) 실제 Vertex AI usage_metadata 실측치 및 BQCA Cached Input 90% 할인($0.30/1M)을 반영한 2-Tier Token 절감 Architecture를 5대 As-Is vs To-Be 직접 대조 Scenario(S1–S5)로 증명합니다.

핵심 과제 1: Root ↔ Sub-Agent State · Stateless 3-Turn Window · 4-Scope Memory · Hybrid Routing 핵심 과제 2: Vertex AI usage_metadata 실측 + BQCA 90% Cached Input 실효 비용 실측 시각 (UTC):
고객 문제상황 1 · State, Stateless, Memory & Routing

기본 ADK Toolset 및 Stateful API 단독 사용 시 한계와 해결책

  • ADK 내장 ask_data_agent (One-Shot Stateless): 매 Turn _get_data_agent_info 탐색을 반복 호출하고 단일 UserMessage 1건만 전송해 2턴 후속 질문에서 선행 조건이 유실됩니다.
  • 관리형 ConversationReference (Stateful): 1 Conversation = 1 고정 DataAgent에 종속되어 타 업무 Domain 전환 시 문맥이 끊기며 동시 병렬 호출이 직렬화됩니다.
  • 제안 Best Practice: 정적 enum transfer_to_agent + Sub-Agent 간 직접 Peer 전환 + ThreadPoolExecutor 병렬 Chat API + 4-Scope State/Memory + App(context_cache_config=...) 격리 Cache 적용.
고객 문제상황 2 · 2-Tier Token 절감 및 90% Cache 비용 최적화

ADK 계층 + BQCA 계층 5단계 Token Diet Pipeline

  • Stage 1–2 (탐색 제거 및 Schema 분리): 런타임 Discovery Tool을 제거하고 110K+ 단일 통합 Agent를 최소 권한 Domain Agent(4 / 3 / 5개 Table)로 분할합니다.
  • Stage 3–4 (양방향 O(1) 상한선 고정): THOUGHT 스트림 제거 + 20행 요약 캡(Turn Scope 즉시 소거), 하위 BQCA 3-Turn Sliding Window (6 Messages) 제한, 상위 ADK before_model_callback 3-Turn 이력 압축을 동시 적용합니다.
  • Stage 5 (실효 과금 최소화): 고정 Prefix 기반 BQCA 90% Cached Input 할인($3.00/1M → $0.30/1M)과 MemoryService 우회(BQCA 0 tok)를 결합합니다.

하위 BQCA Token 및 90% Cache 단일 통합 Agent 기준 110,764+ tok 매번 소모 단일 Agent 내 90% 암시적 Cache 적용되나 이력 선형 증가 11.4K~13.9K 격리 Schema + 고정 Prefix 구간 $0.30/1M(90% 할인)
